How it works

Point a domain at the server and every address on it becomes a working inbox.

01Mail goes to any address
The SMTP server accepts every recipient with no validation. Plain SMTP is always on; STARTTLS on 587 and SMTPS on 465 when SSL is enabled.
MX 10 mail.yourdomain.com
02You open it in the browser
Enter the address and the inbox loads. A WebSocket pushes new messages and deletions in real time, so the page never needs a refresh.
WS /api/ws/:address
03Your tools read it too
Webhooks, IMAP and an MCP server give test suites, mail clients and AI assistants access to the same mailbox.
POST /api/webhooks

Features

Accepts all mail
Any recipient on your domain is accepted. Optionally reject mail not addressed to DOMAIN_NAME.
Real-time inbox
New mail and retention deletions arrive over a WebSocket. The tab’s icon changes when something is unread.
Claim with a password
The first person to claim an address can lock it. Release it later to make it public again.
Webhooks
Per-mailbox POSTs on arrival and deletion, with a test button to check delivery.
IMAP access
Read a claimed mailbox from any mail client using its address and password.
MCP server
AI assistants can list, read and delete mail and manage webhooks over the Model Context Protocol.
Full-text search
Search subject, sender and body within a mailbox, with matches highlighted.
Auto-cleanup
Set EMAIL_RETENTION_HOURS and old mail is deleted on schedule.
Accounts and admin
Optional sign-in, restricted to your domains. Admins can list and open every inbox.

Self-host it

One binary and a SQLite file. Run the published container or build from source with Rust. The web interface starts on port 3000 and SMTP on 2525.

  1. 1Set DOMAIN_NAME in .env.
  2. 2Start the server with Docker Compose or Cargo.
  3. 3Add MX, A and PTR records for your domain. SPF, DKIM and DMARC help deliverability.
Most ISPs block port 25 on residential connections. Use a VPS or dedicated server to receive mail from the internet.
